# Motion spike tools (Board R&D, 2026-11-22)

Engine-neutral, standard library + NumPy/Pillow/SciPy (ComfyUI's embedded Python; no new dependency).

| File | Purpose |
|---|---|
| `motion.py` | solver v2 (structure.v2 + motion.v2: FK chains, joint limits, shoulder shift, PCHIP splines with broken-tangent keys, leg IK to contacts, rigid weapon on the hand bone), raw QA measurements (no default thresholds; directional ones in the character frame, so mirrored clips measure the same), evidence renders |
| `motion_v1.py` | solver v1 (method A, arm IK) - kept for the record; its structure.v1 file was superseded by `structure_brute_hammer.json` v2, so A is reproduced from `attack_hammer_v1_A.motion.json` only with the v1 structure from this branch's history of the R&D folder (not kept). |
| `cmu_amc.py` | ASF/AMC reader + 3D forward kinematics |
| `retarget_cmu.py` | method C: projection, retargeting, contact cleanup, hip clamp, KB wrist rule, phase detection → motion.v2 |
| `data/structure_brute_hammer.json` | benchmark structure (measured on the master art) |
| `data/attack_hammer_B.motion.json` | method B |
| `data/map_cmu79_brute.json`, `data/attack_hammer_C.motion.json` | method C map and its derived motion |

**CMU data is not in this repository** (licence: free for all uses, the data may not be resold even converted; we keep
only derived keys). The Board downloads `79.asf`, `79_01.amc`, `80.asf`, `80_71.amc` from mocap.cs.cmu.edu/subjects/
into `refs/cmu/` next to `data/` (decision K1, 2026-11-22) before running method C.

Run (from the folder holding `data/` and `refs/`):
```
python -I -s motion.py data/structure_brute_hammer.json data/attack_hammer_B.motion.json review_B
python -I -s retarget_cmu.py data/map_cmu79_brute.json data/structure_brute_hammer.json data/attack_hammer_C.motion.json
python -I -s motion.py data/structure_brute_hammer.json data/attack_hammer_C.motion.json review_C
```

## Added after the anatomy and universal-motion amendments (2026-11-22)

| File | Purpose |
|---|---|
| `profiles/*.json` | anatomy profiles (`anatomy-profile.v1`): humanoid base (clinical = normative reference values, functional = task observations, both from kb/human_joint_table.json with per-tier provenance; no value is gate-eligible), stylized and heavy humanoid (overrides carry their own heuristic provenance), quadruped, flying, multi-limbed (heuristic design values), custom template |
| `posecheck.py`, `rules.py`, `motion_rules.json` | validation with the Board's result states (KA-BD-5, 2026-11-23): pass / fail / warn / unknown / not_applicable, each with a reason. Rules carry scope (action category, entity tags, representation), class and enforcement eligibility; only structural invariants (hierarchy, bone length, attachment, grip, rigidity, reachability, declared contacts, weapon vs ground) can fail. Anatomical ranges on the planar rig are 2D proxies of 3D tables and warn at most. Verdict: mandatory fail -> rejected, mandatory unknown -> blocked (artistic items stay unknown until a review record with evidence hashes exists). The motion must declare `category` (for example `strike.heavy_overhead`) |
| `poselib.py`, `data/poses_brute.json`, `poses_brute/` | validated pose library (10 poses + 1 negative example). `poselib.py` now uses the same rule engine; the committed `poses_brute/` entries were generated by the previous validator and are not regenerated |
| `tests/test_motion_system.py` | 29 tests: 8 solver (rest, degrees, inheritance, isolated elbow sweep, weapon, IK reach, knee bend, mirroring) + 10 regression cases from Board-reported failures + 11 validator-semantics cases (unknown never passes, blocking, eligibility, mirrored outcomes, the 140 px ground penetration of B, non-strike scope, provenance of overrides) |
| `entity/` | Entity Motion Profile schema, component registry (`components.json`), 7 example entities, `entity.py plan` (method selection) |

```
python -I -s tests/test_motion_system.py
python -I -s posecheck.py data/structure_brute_hammer.json data/attack_hammer_B.motion.json out.json [--review review.json]
python -I -s poselib.py data/structure_brute_hammer.json data/poses_brute.json poses_out
python -I -s entity/entity.py plan entity/examples/dragon.json
```
